# 备份恢复与审计归档 Runbook

## PostgreSQL 备份

使用与服务端相同或更新主版本的 PostgreSQL Client。数据库密码只通过 `OPSPILOT_DATABASE_URL` 的受保护配置或密码文件进入进程环境，不要把密码写入命令参数。

```powershell
cd backend
python -m app.operations.database_backup create --output D:\secure-backups\opspilot-20260820.dump
python -m app.operations.database_backup verify --backup D:\secure-backups\opspilot-20260820.dump
```

工具使用 `pg_dump --format=custom --no-owner --no-privileges`，拒绝覆盖已有文件，并生成 `.manifest.json`，记录 SHA-256、大小、创建时间和源数据库名称，但不记录主机、用户或密码。备份文件和 manifest 必须一起复制到加密、版本化、限制写入的异地存储。

建议频率：生产环境至少每日全量备份；RPO/RTO 由部署方按业务要求明确。至少每季度执行一次恢复演练，重大迁移前额外执行一次。

## 恢复

恢复只允许写入名称不同的空数据库，并要求操作者再次输入目标数据库名。目标连接串通过环境变量提供，避免进入 Shell 历史。

```powershell
$env:OPSPILOT_RESTORE_DATABASE_URL = "postgresql://restore_user@db/restore_drill"
python -m app.operations.database_backup restore `
  --backup D:\secure-backups\opspilot-20260820.dump `
  --confirm-target-database restore_drill
```

恢复后必须依次检查：

1. `alembic_version` 等于备份源版本；
2. `python -m alembic check` 无待处理迁移；
3. Incident、Action、Approval、Resource Lock、Outbox 和 Audit 行数符合备份时间点；
4. 启动 Control Plane，确认启动恢复扫描成功且 `/api/v1/ready` 为 ready；
5. 使用只读账户抽查 Environment Scope，不在恢复库中启用真实 Runner 或 Webhook。

## 审计归档

默认在线保留 365 天，每批最多 10000 条。归档命令先锁定截止时间之前的旧记录，生成 gzip JSONL 和独立 manifest，完成 fsync 和 SHA-256 后才登记 `audit_archive_batches` 并删除在线源记录。提交前失败会回滚数据库并移除文件；数据库提交结果不明确时保留文件，避免已删除在线记录失去归档副本。

```powershell
cd backend
python -m app.operations.audit_archive --directory D:\secure-audit-archive
python -m app.operations.audit_archive --verify `
  D:\secure-audit-archive\control-plane-audit-....jsonl.gz
```

配置项：

```text
OPSPILOT_AUDIT_RETENTION_DAYS=365
OPSPILOT_AUDIT_ARCHIVE_BATCH_SIZE=10000
```

该命令不会由 Web 进程自动运行。生产环境应通过受限 CronJob/计划任务执行，将目录挂载到独立持久卷，并监控命令退出状态。至少保留两份不可变副本；访问 archive 视同访问生产审计数据库。删除过期 archive 必须遵循组织的数据保留政策和法律要求，不由 OpsPilot 自动执行。

## 故障与证据

- manifest 校验失败：隔离文件，不得删除在线记录或其他副本；
- 归档文件已存在但数据库无批次：视为事务失败后的孤立文件，核对哈希和时间范围后人工处置；
- 恢复目标非空：工具拒绝执行，创建新的隔离数据库；
- 备份或归档可能泄露：轮换相关凭据，限制对象访问，保存处置审计并按 `SECURITY.md` 报告。
